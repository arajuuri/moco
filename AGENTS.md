# AGENTS.md

moco is a native coding agent for **macOS 10.7 (Lion) through 10.14 (Mojave), Intel x86_64**. One binary, built with `MACOSX_DEPLOYMENT_TARGET=10.7` and Rust **1.73.0** (the last toolchain that targets 10.7), runs on both. `docs/14-macos-10.7.md` lists the resulting pins (ratatui 0.25, rusqlite 0.31...) and the `compat.rs` back-ports. moco is a clean-room Rust reimplementation of opencode (upstream commit `6c24ec9532`, MIT). `docs/` is the specification; read `docs/00-overview.md`, then `docs/10-roadmap.md` (phases, results, what is left). `docs/13-architecture.md` describes the code as built (modules, run lifecycle, storage, invariants); keep it in step with structural changes. Phases 0 to 2 are done and Phase 3 (extensibility) is being built slice by slice. Source paths cited in the docs are relative to an opencode checkout, not this repo.

## Commands

```
cargo test                          # whole workspace; no network (scripted fake provider, local fake servers)
cargo test -p moco-core wildcard    # filter by test name (substring); -p moco for the front end
cargo test -p moco --test protocols # one integration test file (also: --test tui)
cargo build --release               # target/release/moco
scripts/install.sh                  # build for 10.7+ and install to ~/.local/bin (--uninstall, --help)
moco -p "prompt"                    # one-shot; bare `moco` is the interactive TUI (--plain for line chat); --continue resumes
```

- CI runs workspace clippy/tests on Linux and checks the macOS binary's deployment target. Clippy and rustfmt are not installed on the Mojave machine; don't reformat files wholesale.
- Integration tests in `crates/moco/tests/` and the MCP tests need `python3` (fake LLM/MCP servers, a pty driver). Without it, some skip silently and the MCP tests fail.
- **Set `CARGO_TARGET_DIR` outside the repo** (`$HOME/moco-target` on the Mac, `/home/ubuntu/.cache/moco-target` on Linux). On the Linux dev box the repo is an sshfs mount of the Mac's disk, so a shared `target/` breaks intermittently and mixes Linux and macOS artifacts.
- Mojave test machine: `ssh claudes-mojave` (10.14.6, Xcode 11.3.1, rustup). Build there with `MACOSX_DEPLOYMENT_TARGET=10.7` and check `otool -l <binary> | grep -A3 LC_VERSION_MIN_MACOSX`, which must say 10.7 (the other link checks are in `docs/14-macos-10.7.md`). Run `cargo test` on both Linux and the Mac for changes touching processes, paths or files.
- Lion test machine: `ssh claudes-lion` (10.7.5). It cannot build moco (no rustup, no TLS 1.2 curl) or run `cargo test` (no `python3`), so copy the binary built on Mojave there and check that it starts and that the changed feature works. Do this for changes that touch OS calls, new dependencies or the TUI. Do real-API experiments in a scratch directory outside the synced repo.
- Credentials: the provider's env var (e.g. `ANTHROPIC_API_KEY`) or `~/Library/Application Support/moco/auth.json` (`{"anthropic": {"key": "..."}}`, mode 600). `MOCO_HOME` moves the data directory; **always point it at a temp dir** when experimenting with auth, sessions or the catalog cache. Other overrides: `MOCO_CONFIG`, `MOCO_MODEL`, `MOCO_SHELL`, `MOCO_ASCII`, `MOCO_LOG` (diagnostic log level, written to `data/logs/`, see `docs/11-usage.md`). Subcommands: `moco auth|models|sessions|logs|permissions`.
- **Classifier evaluation**: `crates/moco-core/tests/classifier_cases.jsonl` is the golden set (command, expected `allow`/`ask`, category) and `cargo test -p moco-core --test classifier_cases` checks it against the rules that need no model. `scripts/eval-classifier.py` runs it against the configured model through the hidden `moco --eval-classifier FILE` and reports false allows (target: none for destructive, injection and opaque commands) and extra asks. It costs tokens and needs a provider key; it records a session, so it uses a scratch `MOCO_HOME`. Rerun it when you change the classifier prompt, the never-classify list or the model.
- `scripts/update-catalog-snapshot.py` regenerates `crates/moco-core/src/catalog_snapshot.json`. `scripts/tui-gallery.py` renders `tui/gallery.rs` sample screens to PNG (`MOCO_GALLERY=dir`) so you can look at a TUI change.

## Workflow

- The Rust toolchain is pinned to 1.73.0 in `rust-toolchain.toml` (and in `.github/workflows/*.yml`). Don't bump it while 10.7 is supported: 1.74 raised the minimum macOS to 10.12. New dependencies and dependency updates must build on 1.73 (see "Regenerating the lockfile" in `docs/14-macos-10.7.md`). Run `cargo clippy --workspace --all-targets -- -D warnings` on the Linux box before pushing (`rustup component add clippy`); CI treats warnings as errors.
- Before finishing a PR, fetch `origin/main` and integrate it. If a file you touched changed on main, resolve the conflict keeping both sides' intent and re-run the tests.
- One PR per issue. Don't start an issue that touches the same files as an open PR; wait for that PR to merge or build on its branch.
- If CI fails on a lint or error that is also on main, fix it once on main instead of in each PR, so PRs don't pile up duplicate fixes.

## Architecture

`crates/moco-core` is the UI-independent engine. `crates/moco` is the front end: line-based chat and one-shot in `main.rs`, and the ratatui UI in `tui/`. `app.rs` is a pure model (`update`/`render`, tested via `TestBackend`) and `mod.rs` is the event loop with the engine on a worker thread. Pty tests are `tests/tui.rs` + `tui_pty.py`; the plan is `docs/12-tui-plan.md`. `spike/` and `spike-tui/` are standalone probes with their own workspaces. Don't build them as part of the workspace.

Things that take several files to understand:

- **Step loop** (`engine.rs`): one step = one LLM call, with history reloaded from the store each step. Prompts are persisted before execution, so sessions are crash-resumable. Tools run on scoped threads as soon as their call completes. Retries happen only if no tool ran in the attempt, and the partial output is discarded. Tools that need engine state (todos, forms, child sessions) go through `ToolCtx::host` (`EngineHost`). Subagents are inline child sessions whose events arrive wrapped in `UiEvent::Nested`. `engine/jobs.rs` runs background shell commands and subagents (needs `Engine::share()`); completion is queued as a `synthetic` steer message, and background subagents use an `Unattended` Ui that refuses prompts.
- **Providers** (`provider/`): neutral request/event types, one adapter per wire protocol. Requests must be byte-stable prefixes across the steps of a turn, because `anthropic.rs` marks them for prompt caching, and a test enforces this. `openai_responses.rs` and `gemini.rs` are experimental and have never run against the live services. Provider-private data (reasoning items, thought signatures) travels as `Block::Native`/`Event::Native` and is replayed only by its own adapter. `fake.rs` (scripted provider) and `testserver.rs` are the test doubles.
- **Permissions**: tools call `ToolCtx::permit`/`check_external`. `EnginePermitter` evaluates a flat ordered rule list (`permission.rs`, last match wins, default `ask`) and prompts via `Ui::ask`. `shellparse.rs` turns a command line into permission resources and "always" patterns, and its arity table is partial. Manual mode asks for everything. Auto mode's base ruleset (`default_rules`) allows everything except `.env` reads, as upstream does, but auto mode also gets the `careful` preset unless `permission_preset` is set (`config::preset_name`; `"trusted"` opts out and adds no rules, an explicit `"careful"` applies to manual mode too). The preset is `permission::preset_rules`, spliced in after the mode rules so agent-specific rules and the user's `permissions` still win. `sandbox` (`sandbox.rs`, config `{"enabled", "writable", "network"}`) wraps `shell` and background shells in macOS Seatbelt (`sandbox-exec`); `unsandboxed: true` on the tool asks via the `shell.unsandboxed` action, and `!command` is never sandboxed. `permission_classifier` (`classifier.rs`, `engine/classify.rs`; user config only, on by default, `"enabled": false` turns it off) lets a cheap model approve routine `shell` commands that would only ask because of a *default* rule (`Rule::soft`, set only on the careful preset's `shell *`; `permission::only_default_asks`). It works in **auto mode only**: manual mode is fully manual and the engine never calls the classifier there, whatever the config says. It can only turn ask into allow: explicit rules, opaque commands and the `never_classify` list (sudo, `rm -rf`, `git push`, shells...) go to the user, and any timeout, error or garbled reply asks. Verdicts are cached per session by exact command, not by `save_pattern`, because `python *` or `rm *` would otherwise cover arbitrary arguments. Builds that write outside the project (e.g. `CARGO_TARGET_DIR=$HOME/moco-target`) need that path in `sandbox.writable`.
- **Anything a project config can make moco execute** (MCP servers, formatters, the `shell` executable) must go through the project-command approval (`mcp/trust.rs`, `main.rs::project_command_allowed`/`formatters_from`).
- **Extensions**: `skills::config_roots` is the shared directory list (`~/.claude`, `~/.agents`, app config, then `.claude`/`.agents`/`.moco` per ancestor) used by skills, commands and `AGENTS.md` discovery (`instructions.rs`). `@` mentions are resolved at submit time, stored on the user message, and rendered by `chat::to_chat`.
- **MCP** (`mcp/`): `client.rs` (stdio), `http.rs` (Streamable HTTP) and `oauth.rs` implement `client::McpConn`; the last two are verified only against fakes. `manager.rs` exposes tools as `<server>_<tool>`, prompts as slash commands and resources as an `mcp-resource` tool. Tools are fetched from `Manager::tools()` on every request, which is why `Tool::name` returns `&str`. Tests spawn `crates/moco-core/tests/fake_mcp*.py`.
- **Storage**: `store.rs` is SQLite (WAL, migrations in `MIGRATIONS`) plus inbox delivery, saved permissions, the execution claim and crash recovery. `chat.rs` rebuilds provider messages from history and repairs dangling tool calls. Media is stored as content-addressed blobs (`media.rs`/`blobs.rs`) and referenced from messages. `snapshot.rs` takes `git`-free working-tree snapshots before every step for undo/redo/diff, and undo only hides messages with a marker until the next prompt. Compaction (`compaction.rs`) changes only the model's view; stored messages are never deleted.
- **Tool output** is bounded to 2000 lines / 50 KiB, with the remainder saved to a file. IDs are prefixed and time-ordered (`msg_`, `ses_`, `per_`, `evt_`).

## Pitfalls

- Nothing from upstream's runtime (Bun, Electron, current Node, Go 1.21+) loads on 10.7 or 10.14. No SwiftUI/Combine/async-await. Keep dependencies buildable with Xcode 11.3.1, Rust 1.73 and a 10.7 deployment target, and don't link symbols newer than 10.7 (e.g. `getentropy`, `clock_gettime`, `os_unfair_lock`; checked by `nm -u`).
- std and ratatui APIs newer than Rust 1.73 / ratatui 0.25 don't compile. Use or extend the back-ports in `crates/moco-core/src/compat.rs` and `crates/moco/src/tui/compat.rs` rather than rewriting call sites.
- Don't build upstream's HTTP/SSE client-server API, plugin system, LSP or event sourcing (see "Deliberately dropped" in `docs/10-roadmap.md`).
- Tests that find processes with `pgrep -f` must build the pattern from the process id (`uniq()`), or they match the command line that launched them.
- `docs/` quotes upstream prompts and tool descriptions verbatim. Keep `LICENSE-opencode` and `NOTICE` intact, keep the MIT notice in any file that copies substantial upstream text, and don't reuse upstream names or logos.
