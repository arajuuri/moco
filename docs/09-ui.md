# UI

Sources: `packages/tui/src/{app.tsx,routes,component,prompt,feature-plugins,config/keybind.ts}`, `packages/app` (web/desktop UI, not read in detail), `packages/session-ui`.
Upstream has a terminal UI (OpenTUI/Solid) and a web/desktop UI sharing the same server API. The rewrite needs one front end; the screen inventory below applies to either.

## Screens

1. **Home** (`routes/home.tsx`, `feature-plugins/home/footer.tsx`): logo, prompt box, footer; recent sessions/projects are reachable via `open.menu`. I did not read the layout in detail.
2. **Session**: transcript + composer; optional right sidebar; optional terminal pane; session tabs across the top (open sessions, unread markers, history back/forward, reopen closed tab, quick-switch slots 1-9).
3. **Diff viewer**: file tree + unified/split diff, hunk navigation, mark file reviewed, switch source (session diff vs working tree vs branch).
4. **Dialogs**: command palette, session list (pin, rename, delete, fork), model picker (favorites, recents, variants, provider list, usage limits), agent picker, MCP servers, skills, themes, settings/config, status, permission prompt, question form, timeline, stash, workspaces/worktrees, update, error details, image preview, shell output.

## Transcript rendering

Row types: user message (text, attachments chips, mentions), synthetic/system notices (dimmed), assistant text (GitHub-flavored Markdown with syntax-highlighted code blocks, tables), reasoning (collapsible, "thinking"), tool calls, shell command blocks (`!cmd` input), compaction marker, agent/model switch markers, retry banner with countdown, errors.

Tool call row: icon + tool name + short argument summary + status (streaming input -> running with spinner -> done/error). Expanded view by tool:
- `read`: path and range; `glob`/`grep`: pattern, count of results; `shell`: command, live output tail, exit status, "background" badge, elapsed time;
- `edit`/`write`/`patch`: path(s) and inline diff (additions/deletions counts); `webfetch`/`websearch`: URL/query; `todowrite`: checklist; `subagent`: child title with link to open the child session (child navigation: up = parent, left/right = siblings, down = picker); `question`/`skill`: inline.
- Option to group consecutive exploratory calls (read/glob/grep) into one summarized row ("exploration grouping") and to cycle transcript verbosity.
- Transcript must stay fast with thousands of rows: virtualize, with a mount budget (`routes/session/mount-budget.ts`).

## Composer

- Multiline input, history (up/down), stash (save/restore drafts), external editor (`$EDITOR`), paste-summary for large pastes.
- `@` mentions: files/directories (frecency-ranked fuzzy completion), agents (route to subagent), skills, MCP resources. Attachments: images and PDFs (drag-drop/paste), converted to media parts.
- `/` commands: built-ins, config commands, MCP prompts, skills.
- `!` prefix runs a shell command directly in the session (shown as a shell message).
- Send while the session is busy: choose **steer** (default, delivered at next step boundary) or **queue**; a queued-prompts dialog lets the user reorder, switch mode, undo or delete.
- Interrupt: `Esc` (`session.interrupt`). `ctrl+b` backgrounds a blocking tool (the running shell command moves to background).

## Sidebar sections
From `feature-plugins/sidebar`: context (token usage vs model limit), usage limits, MCP servers + status, todos, footer. A session diff summary (files changed with +/-) is my suggestion, not confirmed as a sidebar section.

## Notifications
Attention sounds/notifications when a run finishes or needs permission while unfocused (`attention.ts`); toast messages for errors.

## Theming
Theme tokens by semantic role (text, background, borders, diff added/removed, syntax, status colors) with light and dark variants and a custom-theme file format; follow system appearance. Note: macOS 10.14 introduced system Dark Mode: use `NSApp.effectiveAppearance` for AppKit.

## Key bindings (defaults, from `tui/src/config/keybind.ts`)

Leader key `ctrl+x`. All rebindable.

| Action | Default |
|---|---|
| Command palette | `ctrl+p` |
| Exit | `ctrl+c`, `ctrl+d`, `<leader>q` |
| New session / list sessions | `<leader>n` / `<leader>l` |
| Open recent sessions and projects | `ctrl+o` |
| Next/previous session tab | `ctrl+tab`, `alt+down` / `ctrl+shift+tab`, `alt+up` |
| Select tab 1-10 | `<leader>1..0`, `ctrl+1..0` |
| Close / reopen tab | `<leader>w` / `ctrl+shift+t` |
| Rename / delete session | `ctrl+r` / `ctrl+d` |
| Interrupt | `escape` |
| Background blocking tools | `ctrl+b` |
| Compact | `<leader>c` |
| Timeline | `<leader>g` |
| Queued prompts | `<leader>q` (undo `ctrl+u`, delete `ctrl+d`) |
| Toggle sidebar | `<leader>b` |
| Toggle terminal pane | `<leader>t` |
| Model list / cycle recent | `<leader>m` / `f2`, `shift+f2` |
| External editor | `<leader>e` |

On a Mac GUI translate `ctrl` shortcuts to standard `cmd` conventions (Cmd+N new session, Cmd+W close tab, Cmd+Enter send, Cmd+K palette) and keep the leader scheme only for a terminal front end.

## Embedded terminal
Upstream has a PTY pane (`pty`, `persistent-pty`) with a terminal emulator; sessions can own persistent terminals the model can read. For v1 skip the pane. If added: `forkpty`, a VT100/xterm emulator (SwiftTerm on Swift; `vte`/`alacritty_terminal` crates on Rust), resize via `ioctl(TIOCSWINSZ)`.

## moco implementation notes (terminal chat)

What exists is a line-based terminal chat (`crates/moco`), not the full-screen or windowed UI described above; the user-facing commands are in `11-usage.md`. Summary of how the spec's UI concepts map:
- **Transcript**: assistant text streams to stdout; tool calls are one dim `>` line each (subagent activity indented under `[agent]`); failed tools show a red first line; the todo list is printed as a checklist when it changes; there is no collapsible reasoning, syntax highlighting or markdown rendering.
- **Composer**: a single line with `@` mentions of files, images, PDFs, directories, skills and agents (no completion, history, stash or `!` shell commands; no clipboard paste of images). Prompts sent while a turn runs are not possible in this UI (the engine supports steer and queue; the terminal does not expose them yet).
- **Dialogs**: permission prompt, numbered question form, `/model` search, `/sessions` list; no command palette, sidebar, diff viewer pane or theme support. `/diff` prints colored unified diffs.
- **After each turn**: tokens, cost, session cost, cache read and write counts, context fill (the sidebar's "context" section).
- **Interrupt**: `Ctrl-C` (not `Esc`).
