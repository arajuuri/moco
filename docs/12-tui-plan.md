# Full-screen TUI: plan

Status: all six slices done (see Progress). The TUI is the default on a terminal. Screen concepts come from `09-ui.md`; this file decides how moco builds them.

## Progress

- **Slice 1 (skeleton): done.** `moco --tui` (opt-in until the slash commands exist in the TUI; then it becomes the default with `--plain` as the escape). Code: `crates/moco/src/tui/{mod,app,term}.rs`. Transcript (user, streamed assistant text, tool rows with failures, todos, subagent tool rows indented, usage line per run), single-line composer with cursor editing and paste, permission dialog (y / a / n / f for feedback, queued), Esc or Ctrl-C interrupt, PageUp/PageDown/Ctrl-Home/Ctrl-End scrolling, status bar (model, agent, title, session cost, context %, spinner), terminal restore on exit, panic (main thread), SIGTERM and SIGHUP. Not in the TUI yet: slash commands (only `/help`, `/exit`), the `question` form (dismissed with a notice), sending while a run is active, mouse. Tests: 8 model/render tests with `TestBackend`, 2 pty tests (`tests/tui.rs` + `tests/tui_pty.py`: dialog, streaming, resize, Ctrl-D, and SIGTERM while a dialog is open; the second fails if the worker is not released), on Linux and Mojave. Live on Mojave with the real model: a prompt that creates a file ran and exited cleanly. Release binary 10.8 MB, `minos 10.14`.

- **Slice 2 (composer): done.** Multiline composer (Alt-Enter or Ctrl-J adds a line; wrapped lines; grows to 8 rows then scrolls), cursor movement by character, word and line (Ctrl-A/E/U/K/W act on the current line), Up/Down move between visual lines (remembering the column) and then browse prompt history (kept in `data/tui-history`, last 500, drafts are restored), large pastes (6+ lines or 800+ characters) collapse to `[Pasted text #N: L lines]` and expand on send. Completion popup (Tab or Enter accepts, Up/Down select, Esc dismisses): `/` offers `/help`, `/exit`, custom commands and MCP prompts; `@` offers subagents, skills, MCP resources and project files (listed in the background honoring `.gitignore`, ranked by base name, then path, then subsequence; directories keep the popup open; spaces are escaped as `\ `). Custom slash commands and MCP prompts now run in the TUI (a command's `agent`/`model` apply to that one prompt); subagent-style commands are refused with a message; `!command` runs a shell command and shows its output. Not yet: the built-in session/model commands (`/model`, `/sessions`, `/undo`, ...) which arrive with the dialogs in slice 3. Live on Mojave: `/sho` + Tab, `@note` + Tab, Enter, answer, Up recalls the prompt.

- **Slice 3 (dialogs): done.** The `question` tool's form (one question at a time; Enter or 1-9 selects, Space toggles in multiple-choice, "type your own answer", Esc dismisses). Pickers with a type-to-filter box (every word must match): `/model` (connected providers' tool-capable models with context and price), `/agent`, `/sessions [all|archived]` (Enter resumes: the transcript is rebuilt from the stored conversation, undone messages left out), and the `Ctrl-P` command palette (runs argument-free commands, inserts the others into the composer). The built-in commands now work in the TUI: `/model /agent /sessions /resume /new /rename /fork /archive /unarchive /undo /redo /diff /compact /jobs /skills /commands /mcp (status, reconnect, logout)`; `/diff` shows colored patches; `--continue` and `--session` show the stored conversation on start. Built-ins that change the conversation are refused while a turn runs. Not yet: `/mcp auth` (needs the paste prompt), subagent-style custom commands, sending while a turn runs. Live on Mojave with the real model: the model called `question`, the form was answered with `2`, the answer came back; `/model` and `/sessions` pickers; `--continue` replayed the conversation.

- **Slice 4 (while running): done, and the full-screen UI is now the default.** On a terminal, `moco` starts the TUI; `--plain`, `-p` and pipes keep the line-based chat. While a turn runs, Enter sends the text as a **steer** (delivered at the next step boundary), Ctrl-Q or `/queue <text>` as a **queued** prompt (delivered when the turn ends); commands (`/x`, `!x`) still run at once. Waiting prompts show above the composer (`next step>` / `after turn>`) and become user rows in the transcript the moment the engine delivers them (new `UiEvent::Delivered`, so they appear before the output they caused); `/queue` opens a picker (Enter switches steer/queue, Ctrl-D removes; new `Store::inbox_items`/`set_inbox_mode`). A prompt that slipped in as the turn ended is run automatically. `/jobs` opens a picker (Enter shows output, Ctrl-D stops) and the status bar counts running jobs. A subagent's run of tool calls collapses into one line (`[explore] 3 tool calls, 1 failed: now > glob *.rs`; Ctrl-O shows every call). A pending provider retry counts down in the status bar. Still plain-only: `/mcp auth` and subagent-style custom commands (the TUI says so). Live on Mojave with the real model: during `sleep 6` a steered "also add the word banana" came back as "done banana"; tests also check message order in the store.

- **Slice 5 (rendering quality): done.** Assistant text is rendered as Markdown (`tui/md.rs`, no dependency): headings, bullet and numbered lists with hanging indents, quotes, rules, fenced code (never reflowed, shown in the code color), tables (aligned, or one line per row when too wide), inline `code`, **bold**, *italic*, links; half-streamed markers stay literal until closed; control characters are dropped and wide characters wrap by display width. No syntax highlighting. The model's reasoning is shown by detail level. **Detail levels** (Ctrl-O cycles normal, full, compact): compact shows only call lines; normal adds inline diffs for `edit`/`write`/`patch` (built from the call's input with `similar`, 24 lines, "more" marker) and a one-line summary of the reasoning (`thinking (N lines, Ctrl-O shows all) ...`, naming the bound detail key; the last reasoning of a turn that ended without answer text is shown whole, #149); full shows the whole reasoning, every diff line, the first lines of other tools' output and every subagent call. `/diff` opens a full-screen viewer (colored patches, `j`/`k`, Space/`b`, `n`/`p` between files, `g`/`G`, `q`); a permission dialog still appears over it. Only the newest screenful of the transcript is wrapped and rendered each frame (20,000 Markdown rows still render in a few milliseconds; a test enforces it), and scrolling far back renders more on demand. Live on Mojave: an `edit` showed its `-`/`+` lines inline, the bullet list and bold rendered without markers, `/diff` opened the viewer.

- **Slice 6 (polish): done.** All six slices are implemented. **Themes** (`tui.theme`, `/theme`): built-in `dark`, `light`, `mono`; `auto` (default) picks light when `COLORFGBG` says the background is, else dark; theme files `<app dir>/config/themes/<name>.json` or `<project>/.moco/themes/<name>.json` (project wins) with `extends` and one style string per role (`"#ff8700 bold on 238"`); `#rrggbb` is mapped to the nearest of the 256 colors unless `COLORTERM` says truecolor (Terminal.app has none). **Keys** (`tui.keys`, `tui.leader`): the actions interrupt, quit, palette, newline, queue, detail, sidebar, page_up, page_down, top, bottom and leader can be rebound (a key, a list, or `null` to unbind); Ctrl-C always interrupts, clears or quits; mistakes and duplicate keys are shown as warnings at start and the default stays. Leader (Ctrl-X) plus a key runs a command or action (defaults n /new, l /sessions, m /model, a /agent, d /diff, c /compact, u /undo, r /redo, j /jobs, t /theme, h /help, q /exit, b sidebar, o detail, p palette), extendable with `tui.leader`. **Attention**: when a turn ends, a permission is requested or a question is asked while you are away, moco rings the bell and marks the window title (`moco: done`, `moco: read needs permission`; cleared on the next key); away means the terminal reported loss of focus (iTerm2 does; Terminal.app does not) or no key press for `tui.away_after` seconds (default 8); `tui.bell: false` turns it off. The window title is saved and restored (xterm push/pop). **Sidebar** (`tui.sidebar`, leader b): session title, model, agent, context bar, cost, todos, MCP server states, running jobs and waiting prompts; shown by default from 110 columns, never below 76. Live on Mojave with the real model: light theme colors, bell and title mark at the end of a turn, todos in the sidebar, rebound palette key.

- **Visual pass: done.** The look was redesigned after rendering sample screens to PNG (`MOCO_GALLERY=dir cargo test -p moco gallery`, then `scripts/tui-gallery.py scenes.json outdir`; the gallery covers chat, narrow, 80x24, permission, picker, completion, diff viewer, Markdown tour and the welcome screen in dark, light and 256-color variants). Messages you send are cards (accent bar, panel background); replies are indented with a left margin; tool calls read as a timeline (`✓ edit   src/parser.rs`, a pulsing `●` while running, `✗` with the reason when failed); diffs show a `+`/`-` gutter, with a subtle full-line background on truecolor terminals and a gutter-only background on 256-color ones (Terminal.app); code blocks are panel cards with the language on the corner; tables use box-drawing characters; headings, quotes, rules and bullets are accented; the end of a turn is a thin rule carrying the numbers (`── 5.2k in · 640 out · $0.0231 ──`). The composer is a rounded box with a `›` prompt, a placeholder and a key hint; the status bar has a highlighted model segment, a colored context gauge (green, amber, red) and drops its least important parts on narrow terminals; the sidebar has small-caps section headers and status dots; dialogs are rounded boxes (amber for permission requests, the command shown on a card). A welcome card opens each session. New theme roles `panel border ok warn bar_hi`; `tui.ascii` (or `MOCO_ASCII=1`) swaps every drawing character for plain ASCII (a test checks nothing else is drawn). All of this is verified through rendered buffers, scripted terminals and live runs; nobody has yet looked at it in Terminal.app or iTerm2 on the Mojave screen, where fonts and the exact palette will differ from the previews.

## Decisions

- **Library**: ratatui + crossterm, in `crates/moco` behind a new `tui/` module. The line-based chat stays as the fallback (`--plain`, and automatically when stdout is not a terminal), so scripts, `-p` and the protocol tests keep working.
- **Threads, no async**: the UI thread owns the terminal and an `mpsc` channel of `AppEvent` (key, paste, resize, engine event, tick). A reader thread forwards crossterm events; the engine runs on a worker thread per run and its `Ui` implementation (`TuiUi`) turns `UiEvent`s into `AppEvent`s. `Ui::ask` and `ask_questions` block the worker on a reply channel while the UI thread shows the dialog.
- **State is a model, rendering is pure**: `App` (transcript rows, composer, dialog stack, run state, usage) with `update(AppEvent)` and `render(&App, Frame)`. Tests drive `update` with scripted events and render into ratatui's `TestBackend` to assert on the buffer; no terminal needed on Linux.
- **Theme and keys are data**: a `Theme` of semantic roles and a `Keymap` of action names, both loaded from config (`tui.theme`, `tui.keys`), so the Phase 3 "themes, keybinding config" item is part of this work rather than separate.
- **No mouse capture by default**, so the terminal's own selection and copy keep working over SSH; scrolling is by keys (PageUp/PageDown, Ctrl-Home/End).

## Slices

1. **Skeleton**: terminal setup/teardown (also on panic and SIGTERM), event loop, `App`/`render` split, transcript of text and tool rows, one-line composer, run on a worker thread, Ctrl-C/Esc interrupt, status line (model, agent, cost, context fill). Streaming text appended to the last row; follow-tail with manual scroll. Replaces plain streaming for `moco` with no arguments. Mac check in a pty.
2. **Composer**: multiline editing (Alt-Enter newline, word moves, kill, history), bracketed paste (large pastes summarized), `@` completion (files, skills, agents, MCP resources) and `/` command completion, `!command`.
3. **Dialogs**: permission prompt (once / always / reject, with the command or diff shown), question form, model picker, session list (resume, rename, fork, archive), command palette (`Ctrl-P`), help.
4. **While running**: send during a run as steer (default) or queue (the engine already supports both), a queued-prompts panel, background jobs panel (`/jobs`), subagent rows indented and collapsible, todo checklist, retry banner with countdown.
5. **Rendering quality**: Markdown for assistant text (headings, lists, code blocks, tables), collapsible reasoning, inline diffs for `edit`/`write`/`patch`, `/diff` viewer pane, verbosity cycling, wide-character and tab handling, bounded redraw cost on long transcripts (render only the visible window).
6. **Polish**: themes (dark, light, custom file; background color is never assumed, no OSC 11 query needed), keybinding config with the upstream leader scheme (`Ctrl-X`) as the default, terminal bell and title when a run ends or asks permission while unfocused, optional sidebar (context, MCP, todos, jobs) when the terminal is wide enough.

## Risks and open points

- Over a slow SSH link, full redraws are costly: rely on ratatui's diffing and avoid animating more than a spinner.
- Terminal.app limits: no truecolor (256 colors only, so themes need a 256-color mapping), no kitty keys, Option-as-Meta must be enabled by the user for Alt shortcuts (Esc-prefix is accepted as Alt).
- The engine's `run` is blocking and `Ui` is called from tool threads; `TuiUi` must never block the UI thread and never hold a lock while waiting for a dialog answer.
- Alternative if ratatui's text handling proves inadequate for the composer: a small custom editor widget (planned anyway in slice 2) rather than a third-party textarea crate.
