# Providers and models

Sources: `packages/ai/src/{llm,route,protocols,providers}`, `core/src/{provider,model,model-resolver,models-dev,credential}.ts`, `core/src/plugin/provider/*`.
Upstream is a large provider matrix (~50 provider modules, ~45 protocol adapters including image/speech/video). For a rewrite implement a **small set of wire protocols**
and let the catalog supply base URLs.

## Abstraction

```
Model { id, providerID, name, family, capabilities {tools, input: text|image|pdf|audio, output, reasoning}, limit {context, input?, output},
        cost {input, output, cache {read, write}} (USD per million tokens), variants[] (e.g. reasoning effort presets), route {protocol, baseURL, auth} }
Request { system[], messages[], tools[] (name, description, JSON schema), toolChoice, settings (temperature, topP, maxOutput, reasoning...), headers, body overlay }
Stream events: text-start/delta/end, reasoning-start/delta/end, tool-input-start/delta/end, tool-call {id,name,input,providerExecuted?},
               step-finish {reason, usage}, provider-error {code, retryable, retryAfterMs?, contextOverflow?}
Usage { input, output, reasoning, cacheRead, cacheWrite } -> cost via model.cost
```
One interface: `stream(request) -> Stream<event>`; each protocol adapter converts the neutral request to its wire JSON and parses SSE chunks into the neutral events.
Per-model/agent overlays: `request.settings`, extra `headers`, and a raw `body` object merged into the request JSON (config `providers.<id>.models.<id>`, `agents.<id>.request`).

## Wire protocols to implement, in priority order

1. **Anthropic Messages** (`protocols/anthropic-messages.ts`): `POST {baseURL=https://api.anthropic.com/v1}/messages`, headers `x-api-key`, `anthropic-version`, SSE streaming; content blocks text/thinking/tool_use/tool_result/image/document; prompt caching via `cache_control` markers (see `cache-policy.ts`); extended thinking with budget.
2. **OpenAI-compatible Chat Completions** (`protocols/openai-chat.ts`, `openai-compatible-chat.ts`): `POST {baseURL=https://api.openai.com/v1}/chat/completions`, SSE `data:` chunks, `tool_calls` deltas. Covers OpenRouter, Groq, DeepSeek, Together, Fireworks, Ollama, LM Studio, vLLM, etc.: only base URL and key differ.
3. **OpenAI Responses** (`protocols/openai-responses.ts`): `POST /responses`, needed for newer OpenAI models and reasoning items, with encrypted reasoning replay.
4. **Gemini** (`protocols/gemini.ts`) and Vertex variants. Later.
5. Bedrock Converse + event-stream framing. Later (needs SigV4).

I did not read the adapters line by line. When implementing each, use the vendor docs as primary reference and the adapter as a cross-check for edge cases (tool-call id handling, empty-content workarounds, reasoning replay, error classification).

## Error classification (needed by retry)

Map HTTP/transport failures to: `Auth`, `RateLimit(retryAfterMs)`, `ProviderInternal(retryAfterMs)`, `InvalidRequest`, `ContextOverflow`, `ContentFilter`, `Transport(code: Timeout|ECONNRESET|...)`. Retryable: RateLimit, ProviderInternal, Transport. `ContextOverflow` is detected from provider-specific error strings/codes and triggers compaction, not retry (`isContextOverflowFailure`).

## Catalog

Upstream ships a snapshot of the **models.dev** catalog and refreshes it from the network (`core/src/models-dev.ts`, `models-dev/snapshot.txt`). Entries give provider id, env var names for keys, npm-style package (selects the protocol), models with limits/cost/capabilities. In your app: embed a trimmed JSON snapshot, refresh from `https://models.dev/api.json` (verify the URL and schema version yourself; the code accepts v1 `/api.json` and a newer v2 shape), and let `opencode.json`-style config add custom providers/models.

## Selecting the model

Order (`model-resolver.ts`): session-selected model -> agent `model` -> config `model` -> last used / first connected provider default (`model.default`). Model refs look like `provider/model` in config strings, optionally with a variant (`provider/model#variant`; check `schema/src/config/model.ts` parse for the exact separator).

## Credentials

Sources of keys, in order: stored credential (UI "connect"), environment variable named by the catalog entry, config `providers.<id>`. Stored in `auth.json` (mode `0600`, see `02`) in the rewrite, not the Keychain. OAuth flows exist upstream for some providers (ChatGPT, GitHub Copilot, GitLab); skip initially, use API keys. For MCP OAuth see `08`.

## Cost and usage

After each step record usage, compute cost = sum(tokens x price / 1e6) with tier pricing by context size, accumulate on the session (`tokens_*`, `cost`), publish `session.usage.updated`. Sidebar shows context usage vs limit.

## Warming (optional)
Keep cache hot with periodic tiny requests (`config.warming`). Skip.

## moco implementation notes (Phase 2, providers slice)

Code: `catalog.rs`, `provider/{anthropic,openai_chat,registry}.rs`, `auth.rs`.
- **Protocols implemented**: Anthropic Messages and OpenAI-compatible Chat Completions (`POST {base}/chat/completions`, `stream_options.include_usage`, tool calls assembled from deltas, `reasoning_content` shown but not stored, cached tokens read from `prompt_tokens_details`). Chat Completions is used for `api.openai.com` too, with `max_completion_tokens`. OpenAI Responses and Gemini are implemented as **experimental** protocols (see the last section).
- **Catalog**: an embedded snapshot (`catalog_snapshot.json`, 10 providers, regenerate with `scripts/update-catalog-snapshot.py`), replaced by `<app dir>/cache/models.json` after `moco models --refresh` (full models.dev download filtered to usable providers and tool-calling models, about 7,000 models). Only the v1 `api.json` shape is parsed. Providers whose `npm` package is one of the AI SDK OpenAI-compatible families use Chat Completions; a small table supplies base URLs for those without an `api` field. The providers in the embedded snapshot are built in: a downloaded catalog may add models and prices for them, but their `api`, `env` and `npm` always come from the snapshot (#163), so models.dev cannot send a key elsewhere or pick which variable it is read from. A provider only the download knows cannot name a built-in provider's key variable, and a provider's id is always its key in the catalog (it selects the `auth.json` entry). Your own config (`providers.<id>`, below) still overrides all of this.
- **Model refs** are `provider/model` (the first `/` splits, so `openrouter/anthropic/claude-x` works). Resolution: session choice (`/model`, `--model`, `MOCO_MODEL`), then the agent's `model`, then config `model`, then `anthropic/claude-sonnet-5-5`. There is no "last used / first connected" fallback; a missing provider fails with the env var and `moco auth` hint.
- **Credentials**: an environment variable named by the catalog entry (or `<PROVIDER>_API_KEY`) wins over `auth.json`; `moco auth <provider>` reads the key from stdin (echo off on a terminal) and writes `auth.json` with mode 0600, keeping other entries. Provider requests follow no redirects: ureq would strip only `authorization` on the way, so `x-api-key`, `x-goog-api-key` and configured headers would reach the redirect target. A 3xx answer fails the request (not retried) with the address to use as the base URL.
- **Config `providers.<id>`** adds or overrides a provider: `base_url`, `env`, `protocol` (`openai-chat` default for new ones, or `anthropic`), `headers`, `models.<id>` (`name`, `limit{context,output}`, `cost{input,output,cache_read,cache_write}`), `disabled`. `base_url`, `env`, `protocol`, `headers` and the `request`/`variants` overlays (provider and model) are read only from your own config (`<app dir>/config/` and `$MOCO_CONFIG`); a project's `moco.json` that sets them gets a warning and they are ignored, so a cloned repository cannot redirect your saved key to its own server. Providers defined this way need no key (Ollama, LM Studio, vLLM):
```jsonc
{ "providers": { "ollama": { "base_url": "http://localhost:11434/v1",
    "models": { "qwen3-coder": { "limit": { "context": 32768, "output": 8192 } } } } },
  "model": "ollama/qwen3-coder" }
```
- **Cost**: tokens times catalog prices per million, including context tiers (a tier applies when input plus cached tokens exceed its size). Totals are stored on the session (`cost`, `tokens`); the terminal prints tokens, cost, session cost and context fill after each turn. Models without a price show "cost n/a".
- **Not done**: OAuth flows, usage limits, warming. (Variants and request overlays: see the reasoning notes at the end.)
- **Prompt caching (Anthropic protocol)**: `cache_control: {"type":"ephemeral"}` markers on the last tool definition, the system prompt, the last block of the final message and the last block of the message that ended the previous request of the agent loop (four, the API maximum; fewer for short requests). The fourth marker means a step that adds many content blocks still hits the previous step's cache entry exactly instead of relying on the API's lookback window. Default 5-minute lifetime; the 1-hour option is not used. Turn it off per provider with `providers.<id>.prompt_cache: false`. This only pays off if every request extends the previous one byte for byte, which is why the Plan agent's reminder lives in the system prompt (not appended to the last message) and why `every_request_of_a_turn_extends_the_previous_one` exists as a test. A reminder that changes during a turn cannot go in the system prompt or into `messages`, so it travels in `Request::tail`: the Anthropic adapter adds it as a last text block of the final user message after placing the markers, so the cached prefix is byte-identical whatever the tail says, and the other adapters append it to the final user message (`Request::messages_with_tail`). The todo list reminder (issue #70) is the first user of it. Things that do break the prefix and are expected: compaction, a changed `AGENTS.md`, switching model or agent, and the tools-disabled final step. Measured on macOS 10.14 against the live API: a two-step turn cost $0.0105 instead of about $0.016, and follow-up turns in the same session within five minutes cost $0.0006 instead of about $0.015 (the usage line shows `cached` and `cache written` counts).
- **Other protocols**: OpenAI-compatible endpoints cache automatically on the server side and report `cached_tokens`, which is used for pricing; no markers are sent. OpenRouter's Anthropic-backed models would need explicit markers in content parts, which are not implemented.
- **Media**: `Block::Image` and `Block::Document` carry base64 data. Anthropic gets `image` and `document` blocks (`cache_control` can sit on them). OpenAI-compatible endpoints get `image_url` data URIs and, for PDFs, `file` parts; many compatible servers do not accept `file` parts, in which case the provider's error is shown. The catalog `modalities.input` list (snapshot and refresh) tells moco which models accept images or PDFs.

## moco implementation notes (Phase 3, OpenAI Responses and Gemini)

Code: `provider/openai_responses.rs`, `provider/gemini.rs`, `Block::Native` / `Event::Native` in `provider/mod.rs`, `crates/moco/tests/{protocols.rs,fake_llm.py}`.

**Status: experimental.** Both adapters were written from the public API documentation and have only ever talked to local test servers that replay the documented stream shapes; no real key was available. They are labelled `[experimental protocol]` in `moco models`. Expect small mismatches with the live services (field names, error codes, edge cases) on first contact; the failing request body or event is what is needed to fix them.
- **OpenAI Responses** (`POST {base}/responses`, SSE), opt-in per provider: `{"providers": {"openai": {"protocol": "openai-responses"}}}` (any server that implements the endpoint can use it; Chat Completions stays the default so that a defect here cannot break every OpenAI user). Stateless: `store: false`, the whole conversation is sent each time, `instructions` carries the system prompt, tools are `function` tools with `strict: false`, `max_output_tokens`, `tool_choice: none` on the final step. `include: ["reasoning.encrypted_content"]` is always requested; reasoning items and function-call items are stored as they came and replayed verbatim and in order (reasoning first, the original `fc_` item for each call), because reasoning models reject a replayed call whose reasoning item is missing. Events handled: text and reasoning-summary deltas, `output_item.added/done` for function calls and reasoning, `completed`, `incomplete` (`max_output_tokens`, `content_filter`), `failed`, `error`. HTTP errors share the Chat Completions classification; in-stream error codes are mapped (`context_length_exceeded` -> compaction, `rate_limit_exceeded` retried, `insufficient_quota` not, `server_error` retried).
- **Gemini** (`POST {base}/models/{model}:streamGenerateContent?alt=sse`, key in the `x-goog-api-key` header, never in the URL), selected automatically for catalog providers using `@ai-sdk/google` (`google`, base `https://generativelanguage.googleapis.com/v1beta`). Roles are `user`/`model`; the system prompt goes in `systemInstruction`; images and PDFs are `inlineData`. Gemini gives calls no ids and matches function results by *name*, so moco invents call ids and maps them back to names when building a request. A `thoughtSignature` that arrives with a function call is kept and sent back on that call (it is required for some models; signatures on plain text parts are not preserved). Function-declaration schemas are reduced to the OpenAPI subset Gemini accepts (`additionalProperties`, `$schema`, `title`, `default`... dropped, type arrays become `nullable`, enums become string enums, empty `required` names removed); a tool with no parameters declares none. Usage: cached tokens are split out and thinking tokens count as output. There is no end marker in the stream, so a response without a `finishReason` counts as a dropped connection. Errors: `API key not valid` -> auth, `RESOURCE_EXHAUSTED` -> rate limit (honoring `RetryInfo.retryDelay`), too many input tokens -> compaction, safety blocks -> content filter, `MALFORMED_FUNCTION_CALL` -> retried.
- **Replay data** (`Block::Native`): opaque provider-private data stored as `{"type":"native","provider":...,"data":...}` parts in the assistant message, in stream order, and handed back only to the adapter that produced it (the others skip it; a message that is nothing but replay data is not sent). Switching models or providers mid-conversation therefore just drops the old data. If you switch between two *different OpenAI models* on the Responses protocol, reasoning items from the first may be rejected by the second; start a new session or compact in that case.
- **Tests**: unit tests per adapter (stream decoding, finish and error mapping, request bodies, HTTP round trips) plus `crates/moco/tests/protocols.rs`, which runs the real binary against `fake_llm.py` for each protocol; the server itself checks that the second request replays the reasoning item / thought signature, `store: false`, the `include` list and a cleaned schema, and the test fails with its message otherwise. These verify moco against the documented formats, not against the services.

## moco implementation notes (reasoning effort and request overlays)

Code: `provider/effort.rs` (levels per model, per-protocol body shaping, JSON overlay merge), the adapters' `build_body`, `Engine::{effort_levels, desired_effort, effort_info}`, `Session.variant` (migration 5).
- **A level is a name** (`low`, `medium`, `high`, `xhigh`, `max`, `minimal`, `none`). `Request.effort` carries it to the adapter; `Request.overlay` carries config headers and a body object merged last (objects merge deeply, `null` removes a field).
- **Which level is used**: the session's choice (`/effort`, `--effort`, Ctrl-T in the TUI), else `agents.<id>.effort`, else top-level `effort`. A level the model does not offer is ignored (never an error): a session can switch models freely. Unset means the provider's default.
- **Anthropic** (verified live on Mojave with `claude-sonnet-5-5`): Fable/Mythos, Opus 5.5/5/4.8/4.7, Sonnet 5.5/5 and Haiku 5.5 take `thinking: {type: "adaptive", display: "summarized"}` plus `output_config: {effort}` with `low..xhigh, max` (4.6 models: no `xhigh`). Where thinking is always on (Fable, Mythos, Opus 5.5/5, Sonnet 5.5/5, Haiku 5.5) moco sends `adaptive` + `summarized` even with no level chosen, so the reasoning can be shown; the API's default display is "omitted". `none` is offered where the model can think less: `thinking: {type: "disabled"}` (Opus 4.8/4.7/4.6, Sonnet 5/4.6) or `{type: "between_tools"}` (Sonnet 5.5); not for Opus 5.5, Opus 5, Haiku 5.5 or Fable. Older reasoning models (Haiku 4.5, Sonnet 4.5, ...) map low/medium/high/max to `thinking: {type: "enabled", budget_tokens: 2048/8192/16384/32768}` and `max_tokens` is raised above the budget. Temperature and other sampling parameters are never sent (they are rejected on these models).
- **Thinking blocks** (signature and redacted ones) are captured as `Block::Native` parts tagged with the model, and replayed only for the tool-use chain that is still running (after the last message the user wrote), only to the same model, and only while thinking is on. Earlier turns' blocks are left out: newer API versions refuse a request whose earlier history was edited (compaction, undo) with thinking blocks attached, and forks start without them. The cost is that the previous turn's messages are not byte-identical to what was cached when it ran, so the first request of a new turn re-reads that part; changing the level also resets the cache (the API says so).
- **OpenAI Chat** (`reasoning_effort`: minimal, low, medium, high) only for the provider id `openai`; **OpenAI Responses** `reasoning: {effort, summary: "auto"}`; **Gemini** `thinkingConfig` with `includeThoughts` (2.x: budgets 1024/8192/24576, max = dynamic; 3.x: `thinkingLevel` low or high). OpenAI and Gemini are as experimental as their adapters.
- **Custom variants and overlays** in config: `providers.<id>.request` and `.models.<m>.request` (`{headers, body}`) apply to every request; `.models.<m>.variants.<name>` (`{headers, body}`) defines a level of your own (or replaces a built-in one of the same name), which `/effort <name>` selects and which contributes only its overlay. This is how another server that speaks one of the protocols gets its own reasoning switch, for example `{"body": {"reasoning": {"effort": "high"}}}`.
- **Not done**: per-message effort changes within a conversation, a per-agent model-specific level, thinking-budget tuning beyond the four presets, showing reasoning token counts separately.
